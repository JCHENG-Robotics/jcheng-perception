# 矿石场景理解实验设计与验收标准

> 版本：2026-11-26。本文定义 S1 已执行的评测协议，以及 S2–S8 的指标/实验
> 设计。**S1 不设“精度通过”阈值**：本轮没有可信的真实矿石金标准，任何
> AP 数字都只是 baseline 证据，不是验收结论。后续阈值必须由 Board 基于任务
> 需求与实测 baseline 设定，本文只给候选值与理由。

## 1. 基本原则

1. **数据源分开报告**：真实、公开、合成、Mock、仿真分别列，不合并、不加权
   成一个“总精度”。
2. **无 Ground Truth 不报精度**：没有实例 mask GT 的图像只能做定性检查、
   计数/延迟统计，不能报 AP/P/R。
3. **防止泄漏**：同一矿石/同一场景的相邻帧不能同时进训练与测试；按 session/
   场景/矿石分组切分，不按帧随机切。
4. **测试集不调参**：调参集与测试集物理分离；报告调参用了哪些图/seed。
5. **失败不算对**：缺失预测、坏图、后端异常、空场景误报都按规则处理，不能
   静默跳过或算作正确。
6. **可见 != 真实**：2D 指标不证明 3D 精度；3D 指标不证明抓取成功率；仿真/
   合成不证明硬件。

## 3. S1 指标定义

### 3.1 Mask AP

对每个 IoU 阈值 `t ∈ {0.50, 0.55, …, 0.95}`：

1. 每张图内，预测按 `detection_confidence` 降序；
2. 每个预测与尚未匹配的 GT 求 mask IoU，取最大者；
3. 若最大 IoU ≥ t，匹配成功（TP），否则 FP；
4. 汇总所有图的 `(score, TP/FP)`，按 score 降序累计 precision/recall；
5. 用 COCO 全点插值计算 AP：
   `AP_t = Σ (r_i - r_{i-1}) · p_interp(r_i)`。

报告：

- `mask_ap50 = AP_0.50`
- `mask_ap50_95 = mean(AP_t)`
- `mask_ap_by_threshold` 全表
- `gt_instances`、`predicted_instances`、`scenes`

S1 简化（必须随报告说明）：

- 不使用 `iscrowd` 区域（数据集本身 `iscrowd=0`；导入器跳过 crowd）；
- 完全遮挡、可见面积为 0 的 GT 实例不进入计数（没有可观测 mask）；
- 重叠多边形被扁平化为可见 label map，因此 GT 可见面积与 COCO 原义不完全
  一致；
- 预测 mask 是互斥 label image，不处理“同一 GT 被多个预测部分覆盖”的
  COCO 细节。

### 3.2 固定操作点 P/R

- IoU = 0.50；
- score ≥ 0.50 的预测才进入；
- `precision = TP/(TP+FP)`，`recall = TP/(TP+FN)`；
- 没有预测时 precision 记 `null`，不记 1.0。

AP 与操作点是两个口径：AP 用 `score_threshold=0.05` 保留低分预测；操作点用
0.50。报告必须同时给出两个阈值，不能只报一个“精度”。

### 3.3 实例数量误差

- `instance_count_mae = mean(|n_pred - n_gt|)`，按图（场景）平均；
- `instance_count_relative_mae = Σ|n_pred - n_gt| / Σn_gt`；
- 空场景参与 overall 统计（预测应为 0；误报计入误差）；
- 分层统计只对有 GT 的场景做（空场景不作为“无遮挡”层）。

### 3.4 遮挡/粘连

合成数据按场景主导属性分层：

- `none`：没有遮挡/接触实例（S1 中通常只剩空场景，故不单独报 AP）；
- `touching`：存在接触但无明显遮挡；
- `occluded`：存在遮挡比例 ≥0.15 的实例。

报告 `by_occlusion` 的 scenes/GT/AP50/计数 MAE。公开数据没有该属性，标
`unlabelled`，不做该分层。

### 3.5 光照与密度

- `by_illumination`：dark/normal/bright；
- `by_density`：sparse/medium/dense；
- 每层报告 scenes、GT、AP50、计数 MAE。

### 3.6 延迟

- `segmentation_ms`：仅后端 `segment()` 的墙钟时间，不含读写/可视化；
- 报告 P50、P95、max、n；
- 记录环境：Python、OpenCV、NumPy、平台、CPU/GPU、图像尺寸；
- 5 MP 与 640×480 分开，不混算。

### 3.7 鲁棒性（S1 范围）

- 光照：dark/normal/bright 分层；
- 密度：sparse/medium/dense 分层；
- 空场景：误报数；
- 坏输入：结构化失败率（必须 100%）；
- 重叠实例：mask 必须互斥；后端重叠应被拒绝。

S1 **未覆盖**：粉尘、水膜、运动模糊、尺度变化、不同皮带颜色、真实矿石
类别差异。这些列入 S2/S8 数据采集计划。

## 4. S1 实际结果（证据）

来源：`evidence/ore_scene_s1_20261126/`。

| 数据 | 场景/图 | GT 实例 | 预测 | AP50 | AP50-95 | P@0.5 | R@0.5 | 计数 MAE | 延迟 P50/P95 |
|---|---|---|---|---|---|---|---|---|---|
| 合成测试（seed 20261127） | 39 | 600 | 346 | **0.3682** | **0.2114** | 0.7513 | 0.2467 | 6.51 | 14.4 / 22.3 ms |
| 公开 `40_70mm` 调参 | 2 | 2,346 | 890 | 0.0430 | 0.0119 | 0.1339 | 0.0145 | 728.0 | 6.56 / 7.53 s |
| 公开 `40_70mm` 测试 | 8 | 9,208 | 2,860 | **0.0429** | **0.0122** | 0.2751 | 0.0277 | 793.5 | 4.68 / 8.53 s |

合成分层：

| 层 | AP50 | 计数 MAE |
|---|---|---|
| sparse | 0.4619 | 1.5 |
| medium | 0.4324 | 5.5 |
| dense | 0.3331 | 14.17 |
| dark | 0.3821 | — |
| normal | 0.4123 | — |
| bright | 0.3265 | — |
| touching | 0.8000（3 场景/15 GT） | — |
| occluded | 0.3570（33 场景/585 GT） | — |

**解读**：

- 合成 AP 只证明“管线/评测能工作”，不证明真实矿石精度。
- 公开测试 AP50 0.043、计数 MAE 793.5，说明经典 baseline 在密集真实碎石上
  严重欠分割；这是 S1.5 引入深度后端的直接动机。
- 调参与测试 AP50 几乎相同（0.0430 vs 0.0429），说明参数没有在测试集上
  过拟合；但也说明这个 baseline 的能力上限很低。

## 5. S2–S8 指标设计

### 5.1 S2 可见几何

| 指标 | 定义 | 备注 |
|---|---|---|
| 可见中心误差 | `||visible_centroid_pred - visible_centroid_gt||` | 只对可见部分；不是真实质心 |
| 重复性 | 同一静态场景多次观测的 P50/P95 | 分视角/距离 |
| 协方差校准 | NEES / 覆盖率的 χ² 检验 | 需要真值；否则只报协方差轨迹 |
| 深度有效率 | mask ROI 内有效深度比例 | 与误差一起报 |
| 可见 OBB IoU | 3D OBB 的 3D IoU | 只对可见部分 |
| 失败率 | 无深度/TF/尺寸不匹配的比例 | 必须 100% 结构化 |

候选阈值（**待 Board 确认，不是本轮结论**）：

- 静态同视角可见中心 P95 ≤ 5 mm（参考现有固定点 5 mm 门，但矿石/深度可能
  需要放宽）；
- 跨视角可见中心 P95 ≤ 10 mm（参考现有双摄静态结果量级）；
- 深度有效率 ≥ 0.5 的实例才参与几何指标，否则报 `insufficient_depth`。

### 5.2 S3 场景关系

| 指标 | 定义 |
|---|---|
| 关系 precision/recall/F1 | 按谓词分别统计；只对有人工/合成真值的子集 |
| 证据覆盖率 | 有关系中有 `evidence` 的比例（目标 100%） |
| 未知率 | 输出 `unknown` 而不是猜测的比例 |
| 稠密场景耗时 | N=100/500/1000 实例的 P50/P95 |
| schema 合规 | JSON Schema + 迁移 round-trip |

候选阈值：无证据关系 = 0；关系 F1 目标由 S3 合成集 baseline 测量后定。

### 5.3 S4 多视角关联

| 指标 | 定义 |
|---|---|
| 关联 precision/recall/F1 | 以物理实例真值为准 |
| ID switch | 同一物理实例在连续观测中 ID 变化次数 |
| 歧义率 | 输出 `ambiguous` 的比例；不强行匹配 |
| 外参/时间偏移敏感性 | 人为扰动后的指标变化 |

候选阈值（待 Board）：无歧义子集 precision ≥0.95、recall ≥0.80；歧义必须
显式输出，不能靠阈值掩盖。

### 5.4 S5 主动感知

| 指标 | 定义 |
|---|---|
| 可见性增益 | 新视角后实例可见面积/数量提升 |
| 几何覆盖率 | 可见点云/表面覆盖提升 |
| 路径/时间成本 | 到候选视角的运动代价（仿真） |
| 建议有效率 | 可达/无碰撞建议比例 |
| 真机只读合规 | 只记录建议、无运动命令 |

S5 不使用真机自动运动；仿真/离线先行。

### 5.5 S6 抓取可操作性

| 指标 | 定义 |
|---|---|
| 抓取成功率 | 仿真/受控实验的 success/total；必须给样本数与失败分类 |
| 间隙/余量 | 夹爪-矿石间隙、可达余量 |
| 碰撞率 | 规划/仿真碰撞 |
| 弃权率 | 输出“不可操作/不确定”的比例 |
| 5-DoF 约束违反 | 不可达/超工作空间的建议数（应为 0） |

无真机阶段不报“抓取成功率”；只报离线/仿真指标。S8 才做真实成功率。

### 5.6 S7 集成

- 契约：IDL/schema parity、manifest、contract hash、版本兼容；
- Applications：recipe 未知字段拒绝、facts 引用正确、失败 fail-closed；
- Learning：dataset provenance、DQ、mask feature 契约；
- Benchmark：suite 校验、JSONL 严格性、`public` 来源标签、报告可追溯；
- 端到端离线：无 DDS/设备/运动。

### 5.7 S8 真实闭环

- 安全：未授权运动 = 0；停止路径可验证；lease/deadman/stop latch 覆盖；
- 精度：分数据源、分矿石类型/光照/密度；
- 可靠性：连续运行、失败恢复、人工接管；
- 可审计：每次 session 的授权、配置/标定 hash、日志、失败分类；
- 不以仿真/合成替代真实验收。

## 8. 反作弊/反误报规则

1. 禁止在测试集上调参；调参集必须写明。
2. 禁止把 synthetic/public/recorded/hardware 结果合并成一个数。
3. 禁止用 GT 参与推理（包括用 GT mask 过滤预测）。
4. 禁止把空场景/缺失预测算作 TP；空场景误报要计入 FP。
5. 禁止只报最好帧/最好类别；报告全部样本或明确说明抽样规则。
6. 禁止在没有 GT 时说“精度 95%”；只能报定性/计数/延迟。
7. 禁止把可见中心叫真实质心、把可见尺寸叫完整尺寸、把 mask 面积叫体积。
8. 禁止把 SAM/YOLO 的 score 当校准概率；除非有独立校准证据。
9. 禁止在 CI/脚本中触发真机运动；硬件实验必须逐次授权。

## 9. 阈值治理

- S1 的 gate 是**功能/证据 gate**，不是精度 gate：
  - 93 个测试通过；
  - selftest 的空场景/坏图/重叠三项通过；
  - 合成与公开结果分源报告；
  - 失败路径结构化。
- S2 起的精度阈值由 Board 在“任务需求 + 实测 baseline”基础上设定；本文的
  候选值只用于讨论，不能写进验收结论。
- 任何阈值变更必须记录：谁批准、依据、适用数据源、样本量、置信区间。
- 样本量过小（如公开调参 2 张）时，只报描述性统计，不做显著性/达标声明。
