# 矿石场景理解路线图（S0–S8）

> 版本：2026-11-26。状态词表固定：交付 `Complete / In progress / Planned /
> Not started`；验证 `Verified / Partially verified / Unverified / Inconclusive`；
> 仓库状态 `Experimental / Deployed / Frozen / Archived`。
>
> 本轮授权：**S0 + 不影响运行时的 S1 离线技术验证**。S2–S8 只做设计，不提前

> `jcheng-system` 的 `ExecuteMotion`。

## 2. 依赖关系与并行

```text
S0 ──▶ S1 ──▶ S1.5 ──┐
  │        │           ├──▶ S2 ──▶ S3 ──▶ S4 ──▶ S5 ──▶ S6 ──▶ S8
  │        └──▶ S7 ◀───┘           │
  │                                └──▶ S7（契约/数据/评测）
  └──▶ S7（接口提案准备，可提前）
```

可并行：

- S1.5（深度后端）与 S2（深度/几何）可并行，但 S2 的几何字段要先定。
- S3 的 schema v2 可与 S2 并行起草；S3 的关系实现依赖 S2 的 3D 证据。
- S5 的仿真环境补齐可与 S3 并行，但 S5 的验收依赖 S4 的场景状态。
- S7 的契约提案可在 S2/S3 设计稳定后提前，但实现必须等对应能力有证据。
- S6 的 5-DoF 可操作性评分可与 S2/S3 并行做离线原型，不接真机。

## 3. S0 — 调研、架构与接口（本轮完成）

**目标**：回答“用什么、为什么、边界在哪、怎么验证”，并留下可审查的设计。

**前置**：无。

**技术选型**：

- 2D：经典 watershed 作为 S1 可运行 baseline；SAM 2 / MobileSAM 作为 S1.5
  候选；Mask R-CNN/Mask2Former/YOLO-seg 作为对照，受权重许可证约束。
- 3D：复用 `jcheng_perception_core` 的反投影/协方差；Open3D（MIT）只在离线
  工具中使用。
- 场景表达：仓库内版本化 Scene State；不引入重场景图框架。
- 评测：COCO 风格 mask AP；分数据源、分场景属性报告。

**模块边界**：`jcheng_perception_scene` 离线包 + `scripts/ore_scene.py`；不改
edge/fusion、不改 `jcheng-interfaces`、不碰冻结基线。

**输入/输出**：

- 输入：现有仓库只读审查、公开论文/仓库/数据页。
- 输出：`ORE_SCENE_RESEARCH.md`、`ORE_SCENE_UNDERSTANDING.md`、
  `ORE_SCENE_ROADMAP.md`、`SCENE_REPRESENTATION.md`、
  `ORE_SCENE_EVALUATION.md`、`ORE_SCENE_S1.md`。

**实现任务**：

1. 只读审查 7 个仓库的真实接口与门禁。
2. 核实候选论文/仓库/数据集的许可证、权重、算力、维护状态。
3. 定义 Scene State v1 字段、有效性与未知项。
4. 定义 S1 离线验证范围与评测协议。

**测试要求**：无运行时测试；文档中的事实必须能追溯到原始来源。

**验收标准**：

- 5 份设计文档 + S1 验证报告存在，且与代码/事实一致。
- 明确列出未核实项、许可证风险和 Board 待决事项。
- 没有修改 `jcheng-interfaces`、冻结基线或运行时。

**风险**：调研结论过时；公开数据许可证/标注质量误判。缓解：记录核实日期与
来源等级；未核实项不进入选型。

**实机依赖**：无。

## 4. S1 — 离线矿石实例分割 baseline（本轮完成离线验证）

**目标**：建立最小可复现的离线实例分割 baseline，跑通“数据→mask→场景状态→
可视化→JSONL→评测→失败路径”闭环；不声称真实矿石精度。

**前置**：S0 完成。

**技术选型**：

- `classical_watershed.v1.0.0`：Otsu 前景（阈值缩放 0.85）+ 形态学 +
  距离变换 + 全局峰值标记（ratio 0.25）+ 分水岭 + 面积过滤；无学习权重。
- `classical_cc.v1.0.0`：连通域消融，证明分水岭对粘连的增益/局限。
- 深度后端仅保留 `SegmentationBackend` 协议，不在本轮引入权重。

**模块边界**：`jcheng_perception_scene` 离线包；不订阅/发布 ROS；不读设备。

**输入/输出**：

- 输入：合成矿石堆（640×480，39 场景，CC0-1.0）或 COCO 多边形数据。
- 输出：`scenes.jsonl`、`instances.jsonl`、`masks/*.png`、
  `overlays/*.png`、`metrics.json`、`summary.json`。

**实现任务**（已完成）：

1. 包/配置/CLI/7 个子命令。
2. 合成数据生成器（光照×密度×遮挡，确定性 seed，逐实例 GT）。
3. COCO 多边形适配器（局部 ROI 栅格化、重叠扁平化、provenance）。
4. 经典 baseline + 连通域消融。
5. Scene State v1（实例、邻接、有效性、未知项）。
6. mask AP50/50-95、固定操作点 P/R、计数误差、分层、延迟。
7. 空场景、坏图、重叠 mask、缺失数据集、后端异常测试。
8. 公开 `40_70mm` 数据（2 张调参 + 8 张测试）真实域 baseline。

**测试要求**：

- `python3 -m pytest tests -q`：**93 passed**（77 原有 + 16 新增）。
- `python3 scripts/ore_scene.py selftest`：空场景/坏图/重叠三项通过。
- CLI 退出码：0 成功、2 输入/配置、3 后端/运行、4 输出校验。

**验收标准**（本轮实际结果，不是目标阈值）：

| 项 | 结果 | 说明 |
|---|---|---|
| 合成闭环 | 39 场景、600 GT、0 failed | 机制验证 |
| 合成 mask AP50 | **0.3682** | 仅证明 baseline 可运行；不是真实精度 |
| 合成 mask AP50-95 | **0.2114** | 同上 |
| 合成计数 MAE | 6.51（相对 0.423） | 密集场景欠分割 |
| 640×480 延迟 | P50 14.4 ms / P95 22.3 ms | CPU 单进程 |
| 公开真实数据 AP50 | **0.0429**（8 张测试） | 域差距证据；不可接受为产品精度 |
| 公开真实数据计数 MAE | 793.5（相对 0.689） | 预测 2860 / GT 9208 |
| 5 MP 延迟 | P50 4.68 s / P95 8.53 s | CPU 单进程 |
| 空场景 | 0 实例 | 修复了早期 17–18 个假目标 |

**明确未满足**：真实矿石精度、密集实例召回、6 GB GPU 深度后端、深度/3D。

**风险**：合成域与真实域差距；公开标注人工校核状态未知；经典方法欠分割。
缓解：S1.5 深度后端；分数据源报告；不设“通过”结论。

**实机依赖**：无。S1 不连接机器人。

## 5. S1.5 — 深度分割后端对照（Planned）

**目标**：在不改变 S1 契约的前提下，接入 1–2 个许可证干净的深度分割后端，与
经典 baseline 同口径对比，决定 S2 的 mask 来源。

**前置**：S1 完成；依赖/许可证审查通过。

**技术选型**：

- 首选 SAM 2.1 Hiera-Tiny（Apache-2.0，39M 参数；6 GB 未实测）。
- 备选 MobileSAM（Apache-2.0）。
- 不默认引入 YOLO-seg（AGPL）、FastSAM（AGPL）、EdgeSAM（非商用）。

**输入/输出**：同一合成/公开数据集；额外输出后端 ID、权重 SHA-256、显存峰值、
自动 mask 参数、每图延迟；沿用 `scenes.jsonl`  schema。

**实现任务**：

1. 权重下载与 SHA-256 记录；不提交权重。
2. `Sam2Backend`：自动 mask 生成/网格提示；按面积/稳定性过滤。
3. 6 GB 显存与 5 MP 图像的分块/降采样策略。
4. 与经典 baseline 的 AP/计数/延迟/显存对比。
5. 失败路径：CUDA OOM、权重缺失、许可证标记缺失。

**测试要求**：无 GPU 时跳过并报告 `SKIP`，不得伪造结果；有 GPU 时记录显存与
驱动版本；至少 1 个固定 seed 的可重复运行。

**验收标准（建议，待 Board 确认）**：

- 许可证审查表完整（代码/权重/数据集）。
- 在合成集上 AP50 不低于经典 baseline；公开集上至少一项指标（AP50 或计数
  MAE）有可复现改进，否则记录为 `Inconclusive`。
- 6 GB 显存内完成单图推理；5 MP 图有明确的分块/降采样方案。
- 不改变 S1 的 JSONL 契约。

**风险**：SAM 2 对密集小目标召回不足；自动 mask 过滤引入新超参；显存不足。
缓解：先 Tiny、再 Small；保留经典后端；分块评测。

**实机依赖**：无（笔记本 GPU）。

## 6. S2 — 实例级 3D 可见几何（Planned）

**目标**：把实例 mask 与时间匹配的深度/TF 结合，输出**可见**点云、可见中心、
可见尺寸、深度有效率、几何不确定性；不输出真实质心/体积。

**前置**：S1/S1.5 的 mask 稳定；深度对齐（现有 ADR 0004）完成；相机内参/外参
可用。

**技术选型**：

- 复用 `build_observation` 的深度采样/协方差/遮挡逻辑；新增 mask ROI 版本。
- NumPy PCA/AABB/OBB；Open3D 仅离线可视化。
- 深度无效/空洞：显式 `depth_valid_fraction` 与 `missing_fields`，不插值造点。

**输入/输出**：RGB + aligned depth + CameraInfo + TF + mask；输出 `SceneState`
的 `geometry` 字段（schema v2）：`visible_points` 引用、可见中心/协方差、
可见 AABB/OBB、`depth_valid_fraction`、`geometry_status`。

**实现任务**：

1. mask→深度 ROI 采样与有效点过滤。
2. 可见点云、可见中心、PCA OBB、平面/支撑面估计（若适用）。
3. 协方差传播（深度噪声 + 像素噪声 + TF 误差）。
4. 遮挡/边界证据；不推断遮挡方向。
5. 与现有 D435i/Aurora 标定/帧号对齐。
6. 失败路径：深度尺寸不匹配、无有效深度、TF 缺失、外参过期。

**测试要求**：

- 合成深度/固定几何的单元测试（已知平面/立方体）。
- 离线录制回放；至少 1 个静态场景的重复性统计。
- 不允许把 `depth=0` 当有效点；不允许用最近帧替代。

**验收标准（建议，待 Board 确认）**：

- 固定场景、固定视角的可见中心重复性有 P50/P95 与样本数；阈值在 S2 前置实验
  测量后由 Board 设定，本轮不预填。
- 深度有效率、无效点比例、TF 年龄随结果一起报告。
- 所有几何字段标注 `algorithm_estimate`；真实质心/体积仍为 `unknown`。
- 失败场景必须 `valid=false` 且有 `failure_reason`。

**风险**：深度对齐未完成（现有 M4 未完成）；腕部 DDS reader 仍可能 wedge；
反光/粉尘导致深度缺失。缓解：先外机位静态；分视角报告；不接运动。

**实机依赖**：中。需要静态双摄录制/只读真机；每次需操作员授权；不得运动。

## 7. S3 — 结构化 Scene Graph / Scene State（In progress，原型）

**目标**：在 Scene State v2 中表达实例、可见几何、邻近/接触/遮挡证据、
不确定性与缺失字段；为 S4/S7 提供稳定结构。

**前置**：S2 的几何字段稳定；S1 的 schema v1 已冻结。

**技术选型**：轻量对象图（实例节点 + 关系边），不引入图数据库；关系谓词先
固定白名单（`adjacent`、`touching`、`occludes`、`supported_by`），每个谓词
必须有证据字段。多视角/跨帧身份不在 S3 承诺。

**输入/输出**：SceneState v2 JSON/JSONL；关系带 `confidence`、`evidence`、
`source`、`depth_order`；`field_status` 区分 direct/estimate/unknown。

**实现任务**：

1. schema v2 与迁移（v1→v2，不破坏 v1 读取）。
2. 3D 邻接/接触/支撑关系；遮挡方向仅在有多视角/深度顺序证据时输出。
3. 关系置信度与证据（距离、接触像素、深度差、可见性）。
4. 稠密场景的空间索引（避免 O(N²)）；关系数量上限与截断标记。
5. 场景摘要（实例数、空场景、失败原因、未知项）。

**测试要求**：关系真值的合成场景；遮挡方向不得在单视角被推断；schema 迁移
round-trip；大场景性能基准。

**验收标准（建议，待 Board 确认）**：

- 每个关系都能追溯到证据；无证据时输出 `unknown`，不输出默认关系。
- schema v2 通过 JSON Schema 校验；v1 记录仍可读。
- 关系准确率在合成集上报告，真实集仅报告可核验子集。
- 稠密场景不出现 O(N²) 运行时间爆炸。

**风险**：关系真值难标注；遮挡方向易误判；schema 膨胀。缓解：先少谓词、
强证据；关系白名单；Board 评审后再扩。

**实机依赖**：无（离线）；S4 才需要多视角。

## 8. S4 — 多视角实例关联与场景融合（S4.1 生成器已实现；匹配器未实现）

**目标**：把外机位/腕部同一物理实例关联起来，形成跨视角一致的场景状态；输出
关联置信度与证据，不把关联 ID 当客观真值。

**详细设计**：[`ORE_SCENE_S4.md`](ORE_SCENE_S4.md)（2026-11-26，Design）。
**S4.1 已完成**：[`ORE_SCENE_S4_1.md`](ORE_SCENE_S4_1.md)（2026-11-27，
离线合成双视角生成器；只有数据与真值，没有关联匹配器/指标）。本节只是摘要；
门控、数据模型、评测协议与待 Board 决策以设计稿为准。

**前置**：S2 几何可用；S3 schema v2 稳定；双摄时间同步/标定可用。

**技术选型**：以互相投影支持（一个视角的可见点投影到另一视角的实例 mask 内，
且深度一致）为主证据；对称 Chamfer、尺寸相容性、支撑面/关系上下文为辅；
可见质心 Mahalanobis 只作弱先验，因为两视角看到不同表面，可见质心不相等。
匈牙利匹配 + `ambiguity_margin`；不做强制一对一。SAM 2 视频传播仅作研究对照，
不作为身份真值。

**输入/输出**：两路 `SceneState` v2 + 内参/外参/时间戳；输出独立的
`jcheng.scene_association.v1`（设计提案，未入契约），含 `clusters`、
`associated`/`ambiguous`/`singleton`、`association_confidence`、
`association_evidence`、`unmatched_reason` 和单视角原始证据引用。

**实现任务**：

1. 离线合成双视角生成器（已知外参、实例 mask+depth、遮挡）。
2. 候选生成（时间/视锥/AABB/尺寸门控）+ 互相投影支持 + 匈牙利。
3. 可见几何融合/不确定性；保留单视角证据。
4. 关联失败/歧义显式输出。
5. 评测 CLI（配对/聚类/敏感性/消融）。
6. 离线双摄回放与静态真机只读验证（逐次授权）。

**测试要求**：合成双视角真值；同一矿石/相邻矿石的混淆矩阵；时间偏移/外参
误差敏感性；空场景/单视角缺失；置换不变性与确定性；歧义不强制 ID。

**验收标准（建议，待 Board 确认）**：

- 合成 easy pair F1 ≥0.95、dense/occluded ≥0.80（建议值，未跑）；
- 歧义构造正确标记 ≥0.90，且 ambiguous 绝不输出唯一 `global_id`；
- 真实集只报告人工核验子集，不设最低 F1；
- 每个关联有证据；不修改 `jcheng-system` 运动路径；不发布运动命令。

**风险**：可见表面差异导致质心偏移（历史静态实验曾出现 10–14 mm 常数偏移，
疑似外参；另一轮 AprilTag 为 3.37 mm）；遮挡导致单视角缺失；外参误差。
缓解：主证据用互相投影支持；显式 `occluded`/`ambiguous`；先静态、同场景、
已知目标；分视角报告；不接运动。

**实机依赖**：中高。需要双摄静态录制/只读真机；逐次授权。S4.1–S4.4 可完全
离线。

## 9. S5 — 主动感知 / Next Best View（Planned）

**目标**：在场景不确定/遮挡严重时，建议下一最佳观测位姿（或视角），提高实例
可见性与几何完整性；只输出建议，不直接运动。

**前置**：S4 场景状态；S2 几何/不确定度；仿真或离线重放环境；运动接口安全
评审。

**技术选型**：基于占据/可见性/信息增益的候选位姿评分；任务驱动（抓取候选
覆盖率）；先离线/仿真，后真机只读。参考 NBV 综述（2025）与现有
`jcheng-simulation` 域 43 隔离。

**输入/输出**：当前 `SceneState` + 候选视角/位姿；输出排序的 NBV 建议、预期
信息增益、风险/不可达原因；不发布运动。

**实现任务**：

1. 场景不确定度/遮挡度量。
2. 候选位姿生成与可见性/信息增益评分。
3. 与 `jcheng-simulation` 的离线闭环（需先补深度/真值）。
4. 真机只读验证：只记录建议，不执行。

**测试要求**：合成场景的已知最优视角对照；候选评分单调性；不可达/碰撞风险
过滤；禁止在 CI 中触发运动。

**验收标准（建议，待 Board 确认）**：

- 在仿真/离线集中，NBV 建议使目标可见性/几何覆盖率有可复现提升。
- 每个建议有评分与证据；不可达/高风险建议被拒绝。
- 真机阶段只读，需操作员逐次授权；不得自动执行。

**风险**：仿真无深度/实例真值（当前事实）；NBV 评分与真实抓取收益不一致；
运动安全边界。缓解：先补仿真传感器；S5 不接运动；S8 前单独评审。

**实机依赖**：高。仿真先行；真机需安全评审与授权。

## 10. S6 — 抓取可操作性评估（Planned）

**目标**：在实例可见几何/关系基础上，输出候选抓取区域与可操作性评分，明确
5-DoF + 夹爪约束、碰撞/可达性/不确定性；不输出“可抓取”布尔真值，不直接运动。

**前置**：S2/S3/S4 场景状态；5-DoF 运动学/工作空间模型；夹爪几何；离线抓取
仿真或标注。

**技术选型**：

- 自研几何评分（可见点云、局部曲率/平面、夹爪开度、接近方向、碰撞）。
- 研究对照：GraspNet baseline（仅学术非商用）、AnyGrasp（闭源授权）、
  Contact-GraspNet（≥8 GB）——均不作为默认交付。
- 仿真候选：`jcheng-simulation` 需补夹爪/矿石资产与真值。

**输入/输出**：`SceneState` + 机器人/夹爪模型；输出 `GraspAffordance` 建议
（候选区域、评分、证据、未知项、拒绝原因），不发布 `ExecuteMotion`。

**实现任务**：

1. 5-DoF 可达/工作空间过滤。
2. 可见几何的抓取候选生成与评分。
3. 碰撞/自碰撞/夹爪开度检查（平台无自碰撞模型，需显式声明）。
4. 不确定性与失败原因。
5. 离线/仿真评测；真机仅建议、不执行。

**测试要求**：合成几何的已知可抓/不可抓用例；5-DoF 约束；空场景/单视角；
禁止输出运动命令。

**验收标准（建议，待 Board 确认）**：

- 候选评分与离线抓取成功率的相关性可复现；失败原因可解释。
- 不把可见中心当抓取位姿；每个候选有证据与未知项。
- 真机阶段仅建议；S8 前不做自动抓取。

**风险**：5-DoF 限制；无自碰撞/力控/编码器；矿石不规则；抓取真值昂贵。
缓解：先几何评分与仿真；不承诺成功率；S8 单独安全评审。

**实机依赖**：高。仿真/离线优先；真机需授权与安全评审。

## 11. S7 — Applications / Learning / Benchmark 集成（Planned）

**目标**：让场景状态以**契约化、只读、可评测**的方式进入下游；不绕过
`jcheng-system`。

**前置**：S3 schema 稳定；S1/S2 证据可复现；契约提案批准。

**技术选型**：

- `jcheng-interfaces`：新增感知/场景消息与 JSON schema（先提案）。
- `jcheng-applications`：recipe facts 扩展为可引用 `scene_id`/`instance_id`/
  `grasp_affordance`；仍只经 gateway。
- `jcheng-learning`：新增 mask/segmentation feature 与数据契约；不把场景状态
  当动作真值；LeRobot 导出是否包含 mask 需单独设计。
- `jcheng-benchmark`：扩展 `data_source` 支持 `public`；增加图像/mask 指标或
  以数字指标 + 外带 artifact 的方式接入；JSONL 保持严格校验。

**输入/输出**：场景 JSONL/消息、评测报告、数据集 manifest；下游 recipe/
dataset/benchmark suite。

**实现任务**：

1. 契约提案与兼容性评估（0.y.z 规则；ROS 2 type hash）。
2. Applications recipe schema 扩展与 fail-closed 校验。
3. Learning 数据契约扩展与 provenance/DQ。
4. Benchmark suite 扩展与 public 来源标签。
5. 端到端离线集成测试（无运动）。

**测试要求**：契约 parity/manifest/hash；recipe 未知字段拒绝；Learning DQ；
Benchmark 报告 provenance；无 DDS/设备/运动。

**验收标准（建议，待 Board 确认）**：

- 契约变更经批准、tag/manifest/hash 一致。
- 下游能读取场景状态但不获得运动权限。
- 公开/合成/真实数据在报告中严格分离。
- 端到端离线测试通过；真机运动仍不在 S7 范围。

**风险**：契约膨胀；下游把 advisory 当测量；Benchmark 只支持数值指标。
缓解：最小字段集；`truth/verification` 显式；先数字指标后 artifact。

**实机依赖**：无（离线/契约）；S8 才接运动。

## 12. S8 — 真实矿石分拣闭环（Not started）

**目标**：在真实产线/实验台上完成“感知→场景状态→抓取建议→系统运动→结果
复核”的闭环，并给出可审计的安全与精度证据。

**前置**：S1–S7 完成；安全评审；逐次操作员授权；硬件改造（夹爪/传感/急停
缺口评估）；真实矿石数据与标注。

**技术选型**：由 S1–S7 的证据决定；运动只经 `jcheng-system` 的
`ExecuteMotion`；场景状态只 advisory。

**输入/输出**：真实矿石堆/皮带场景；输出分拣结果、成功率、失败分类、证据
bundle；不把单次演示当验收。

**实现任务**：

1. 真实数据采集/标注/域适配（含粉尘、光照、振动）。
2. 在线只读场景状态与健康监控。
3. 抓取建议→系统 motion 的安全集成（lease/deadman/stop）。
4. 失败恢复与人工接管。
5. 分批次验收与回归。

**测试要求**：安全状态机/租约/停止锁存；空场景/误检/遮挡/通信中断；真机
逐次授权；失败可复现。

**验收标准（建议，待 Board 确认）**：

- 安全：无未授权运动；停止路径可验证；无 e-stop 的平台风险被明确接受。
- 精度：分数据源报告；真实矿石指标达到 Board 设定阈值（不得由本轮预设）。
- 可审计：每次 session 有授权、配置/标定 hash、日志、失败分类。
- 不以合成/仿真结果替代真实验收。

**风险**：平台无 e-stop/编码器/自碰撞模型；总线读无超时；粉尘/振动；真实
标注昂贵。缓解：安全评审、限速/限位、人工监督、分批上线；不满足则停在 S7。

**实机依赖**：极高。每一阶段都需操作员授权；禁止 CI/脚本触发运动。

## 13. 阶段门（Gate）与停止条件

| Gate | 条件 | 不通过时 |
|---|---|---|
| G0 | S0 文档评审通过；许可证/未核实项清单完整 | 不进入 S1 |
| G1 | S1 测试/自检/证据通过；合成与公开分开报告 | 不进入 S1.5/S2 |
| G1.5 | 深度后端许可证/6 GB/同口径对比通过 | 保持经典 baseline，S2 用经典 mask |
| G2 | 深度对齐、几何重复性、失败路径通过 | 不进入 S3/S4 |
| G3 | schema v2/关系证据/性能通过 | 不进入 S4/S7 |
| G4 | 多视角关联证据/歧义处理通过 | 不进入 S5/S6 |
| G5 | NBV 仅建议、仿真验证通过 | 不接真机 |
| G6 | 抓取建议离线/仿真验证通过 | 不接 S8 |
| G7 | 契约批准、下游离线集成通过 | 不接 S8 |
| G8 | 安全评审 + 操作员授权 + 分批验收 | 停止，不闭环 |

**3 次失败停止规则**：同一阶段连续 3 次可复现失败，停止自动重试，转入故障
记录/文档模式，等待 Board 决策。
